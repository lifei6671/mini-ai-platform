# 我从零学模型训练（一）：从搭环境到弄清模型训练本质

## 一、前言：所谓“训练模型”，到底是在训练什么？

现在大模型很火。

ChatGPT、Qwen、DeepSeek，以及各种所谓的 SFT、LoRA、QLoRA、强化学习，看多了以后，很容易给人一种感觉：

> 训练模型是一件非常高深的事情，没有几十张 GPU，没有高深数学基础，根本碰不了。

我以前其实也有这种感觉。

但真正开始学习以后，我发现如果暂时把“大模型”三个字拿掉，模型训练最基础的逻辑并没有想象中复杂。

我们可以先把模型理解成一个：

> **有一个给定的函数，如果要得到正确解，就需要调整函数里各个参数，使函数的计算输出趋近于我们期望的值。**

比如最简单的一元二次方程式：

```text
y = 2x + 1
```

输入：

```text
x = 1
```

输出就是：

```text
y = 3
```

如果我们现在不知道 `2` 和 `1` 是多少，只知道很多这样的数据：

```text
x = 1 → y = 3
x = 2 → y = 5
x = 3 → y = 7
x = 4 → y = 9
```

能不能让计算机自己从这些数据里找到：

```text
2
```

和：

```text
1
```

呢？

可以。

这个过程，本质上就是一种最简单的**模型训练**。

我们先随便给模型两个参数：

```text
weight = 0.5
bias = 0.2
```

通过模型的计算，发现模型输出的不准。

于是我们不断告诉模型：

```text
你刚才猜错了多少？
↓
你的参数应该往哪个方向调整？
↓
调整一点
↓
再猜一次
```

反复几百、几千次以后：

```text
weight → 越来越接近 2
bias   → 越来越接近 1
```

模型就“学会”了。

所以我现在更愿意把模型训练理解成：

> **准备训练数据，通过不断计算预测误差，逐渐调整模型内部的参数，让模型的输出越来越符合我们期待的结果。**

大语言模型当然复杂得多。

它内部不是：

```text
2 个参数
```

而是可能：

```text
5 亿
15 亿
70 亿
甚至几千亿个参数
```

模型结构也不是简单的 `y = wx + b`，而是大量矩阵运算、Attention、非线性变换堆叠起来的神经网络。

但最底层的训练思想没有发生根本变化：

```text
给数据
↓
模型预测
↓
发现预测有误差
↓
计算参数怎么调整
↓
调整参数
↓
继续训练
```

所以我的第一天目标不是训练 Qwen，也不是直接学习 LoRA。

而是先解决三个问题：

```text
模型训练需要什么环境？

模型到底是什么？

模型究竟是怎么“学”的？
```

---

## 二、模型训练使用什么语言和框架？

### 1. 为什么几乎都在用 Python？

如果准备学习 AI 模型训练，目前最先应该掌握的语言还是：

```text
Python
```

当然了，使用 Python 不是说大模型是使用 Python 来计算海量数据的。

真正的大量矩阵计算最终还是交给 C++、CUDA、GPU Kernel 等底层实现完成。

Python 更像模型训练领域的：

> **控制层和开发接口。**

现在主流机器学习生态，包括 PyTorch、JAX、TensorFlow，以及后面我们会使用的 Transformers、Datasets、PEFT 等工具，主要都以 Python 作为用户侧开发语言。JAX 官方本身也将其定义为面向高性能数值计算和大规模机器学习的 Python 库。

所以即便平时主要写：

```text
Go
Java
Rust
C++
```

到了模型训练这一层，大概率还是要写 Python。

我目前选择的训练框架是：

## 三、换一张 GPU，需要换训练框架吗？

这是我开始学习之前也比较好奇的问题。

答案是：

> **通常不需要因为换 GPU 品牌，就把 PyTorch 整套代码推翻重写。**

但需要更换 GPU 的**计算后端**。

例如：

| GPU           | 常见计算后端      | PyTorch      |
| ------------- | ----------- | ------------ |
| NVIDIA        | CUDA        | PyTorch CUDA |
| AMD           | ROCm / HIP  | PyTorch ROCm |
| Intel         | XPU / SYCL  | PyTorch XPU  |
| Apple Silicon | Metal / MPS | PyTorch MPS  |

PyTorch 对 AMD 做了比较有意思的一层兼容：ROCm/HIP 版本甚至有意复用了很多 `torch.cuda` 接口，因此不少 PyTorch CUDA 模型迁移到 AMD 时，Python 模型代码可以保持基本不变。

Intel GPU 现在则有独立的：

```python
torch.xpu
```

后端。

Mac 的 Apple Silicon 可以使用：

```python
device = torch.device("mps")
```

利用 Metal GPU。

所以真正变化的往往是：

```text
PyTorch 安装包
GPU Runtime
device 配置
底层 Kernel
某些第三方库
```

而不是整个训练思想。

当然，实际的大模型生态里还会碰到：

```text
FlashAttention
bitsandbytes
Triton
自定义 CUDA Kernel
```

这些工具的硬件支持并不一定完全一致。

所以：

> **PyTorch 本身可以跨硬件，但整个 AI 软件栈未必百分之百无缝迁移。**

第一天暂时不用深究这个问题。

## 七、CUDA 到底要安装什么？

这是新手最容易搞乱的地方。

我们经常把下面这些东西都叫“CUDA”：

```text
NVIDIA Driver
CUDA Driver
CUDA Runtime
CUDA Toolkit
cuDNN
```

实际上它们不是同一个东西。

对于我的学习环境：

```text
Windows + WSL2 + NVIDIA GPU
```

最关键的是：

> **Windows 先安装支持 WSL CUDA 的 NVIDIA 驱动。**

NVIDIA 官方说明，Windows 的 NVIDIA Driver 会把 CUDA Driver 能力暴露给 WSL，因此**不要再在 WSL 内安装一套 NVIDIA Linux 显卡驱动**。

这一点非常重要。

不要看到 Ubuntu 就随手：

```bash
sudo apt install nvidia-driver-xxx
```

---

### 那 CUDA Toolkit 呢？

如果只是：

```text
安装 PyTorch
运行模型
训练模型
```

使用 PyTorch 官方提供的 CUDA Wheel 时，通常没必要为了第一天学习再单独安装一套完整 CUDA Toolkit。

例如我当前使用：

```text
PyTorch 2.12.1
CUDA Runtime 13.0
```

官方对应安装方式是：

```bash
python -m pip install \
    torch==2.12.1 \
    torchvision==0.27.1 \
    --index-url https://download.pytorch.org/whl/cu130
```

PyTorch 官方同时提供 CUDA 12.6、13.0、13.2 等不同 Wheel。

如果以后要：

```text
使用 nvcc
编译 CUDA 程序
编译自定义 CUDA Extension
开发 CUDA Kernel
```

再专门安装 CUDA Toolkit。

第一天不需要把环境复杂化。

我另外安装：

```bash
python -m pip install numpy
```

`numpy` 库不是必须的，但是如果不安装，在运行的时候可能有一条警告。

## 十一、初试模型训练：模型到底是什么？

现在开始真正训练。

先不要直接碰大模型。

我们还是从最简单的小模型：

```text
y = 2x + 1
```

开始。

模型可以粗略拆成两部分：

```text
模型
=
模型结构
+
模型参数
```

例如：

```text
y = weight * x + bias
```

这里：

```text
weight
bias
```

就是参数。

结构规定：

```text
输入到底怎么计算
```

参数决定：

```text
具体算出什么结果
```

所以，我们今天训练的本质就是：

> **保持这个模型结构不变，通过训练寻找合适的 weight 和 bias。**

---

## 十二、第一段训练代码

创建：

```text
01_torch_training_loop.py
```

代码：

```python
import torch
import torch.nn as nn
import torch.optim as optim


device = torch.device(
    "cuda" if torch.cuda.is_available() else "cpu"
)


# 4 条训练数据
x = torch.tensor(
    [[1.0], [2.0], [3.0], [4.0]],
    device=device,
)

y = torch.tensor(
    [[3.0], [5.0], [7.0], [9.0]],
    device=device,
)


# 创建一个简单的线性模型
model = nn.Linear(1, 1).to(device)


# 损失函数
loss_fn = nn.MSELoss()


# 优化器
optimizer = optim.SGD(
    model.parameters(),
    lr=0.01,
)


print("=== BEFORE TRAINING ===")
print("weight:", model.weight.data)
print("bias:", model.bias.data)


for step in range(1000):

    # 1. 使用模型预测
    prediction = model(x)

    # 2. 计算预测误差
    loss = loss_fn(prediction, y)

    # 3. 清除旧梯度
    optimizer.zero_grad()

    # 4. 计算梯度
    loss.backward()

    # 5. 更新模型参数
    optimizer.step()

    if step % 100 == 0:
        print(
            f"step={step:4d}",
            f"loss={loss.item():.6f}",
        )


print("\n=== AFTER TRAINING ===")
print("weight:", model.weight.data)
print("bias:", model.bias.data)


test_x = torch.tensor([[10.0]], device=device)

with torch.no_grad():
    prediction = model(test_x)

print("\n10 ->", prediction.item())
```

我的一次真实结果是：

```text
=== BEFORE TRAINING ===

weight: 0.5720
bias:   0.2282

step=0   loss=21.400826
step=100 loss=0.006028
step=500 loss=0.000548
step=900 loss=0.000050

=== AFTER TRAINING ===

weight: 2.0043
bias:   0.9872

10 -> 21.0307
```

而真实公式：

```text
2 * 10 + 1 = 21
```

模型最后预测：

```text
21.03
```

已经非常接近。

## 十三、接下来把这段代码彻底拆开

### 1. x 是什么？

```python
x = torch.tensor(...)
```

`x` 是：

> **模型的输入。**

比如：

```text
x = 1
```

也可以理解为数学里一个方程式中的变量 `x`。

---

### 2. y 是什么？

```python
y = torch.tensor(...)
```

`y` 是：

> **我们希望模型得到的正确答案。**

也可以叫：

```text
Target
Label
```

例如：

```text
x = 1
y = 3
```

可以理解为数学里方程式计算的结果 `y`。

这里的 `x` 和 `y` 恰好和我们数学里的函数相反，一般情况下一个函数 $y＝f(x) +1$ 的函数，一般情况下我们是已知 `x` 的值，输出 `y` 的值，这是典型的大模型推理过程。

训练是相反，我们知道 `x` 和 `y` 你需要调节函数里的其他变量，让这个函数计算达到平衡。注意，这类是平衡，也就是无限接近于等于 `y` ，而不可能一定等于 `y` 。

---

## 十四、什么是 Sample？

一条：

```text
Input + Target
```

组成一个训练 Sample。

例如：

```text
Sample 1：

Input:
x = 1

Target:
y = 3
```

我们代码里：

```text
x = [1, 2, 3, 4]

y = [3, 5, 7, 9]
```

实际上提供了：

```text
4 个 Sample
```

可以理解为训练过程的样本或我们提供的数据中，一条输入和输出就组成了一个 sample。

---

## 十五、nn.Linear(1, 1) 在干什么？

```python
model = nn.Linear(1, 1)
```

这里不是在告诉 PyTorch：

```text
weight = 2
bias = 1
```

如果我们已经告诉它答案，就没必要训练了。

`Linear(1, 1)` 的意思是：

```text
输入特征数 = 1
输出特征数 = 1
```

然后 PyTorch 创建两个可训练参数：

```text
weight
bias
```

模型计算类似：

```text
prediction = weight * x + bias
```

刚创建时，PyTorch 会初始化这些参数。

比如：

```text
weight = 0.572
bias = 0.228
```

训练就是让它们逐渐变化。

---

## 十六、prediction 是什么？

这一句：

```python
prediction = model(x)
```

得到的：

```text
prediction
```

就是：

> **模型当前的预测结果。**

注意三个东西不要混：

```text
x           输入
y           正确答案
prediction  模型猜出来的答案
```

还未经过训练的模型，在有输入的情况下，一定能得到一个解`y`，可能这个解很离谱，据我们期望值差距很大，但是也是能得到一个值的。

---

## 十七、什么是 Forward？

执行：

```python
prediction = model(x)
```

这一过程叫：

```text
Forward
```

也就是前向传播。

对于当前模型，就是：

```text
拿当前 weight + 当前 bias + 输入 x

计算 prediction
```

例如：

```text
weight = 1
bias = 1
x = 1
```

得到：

```text
prediction = 2
```

Forward 的本质可以先理解为：

> **模型使用当前参数完成一次计算和预测。**

它不会修改参数。

---

## 十八、Loss 是什么？

现在：

```text
prediction = 2
```

但是我们期望得到的值为：

```text
y = 3
```

那么，怎么衡量模型到底错了多少？

就需要：

```text
Loss
```

Loss 可以理解成：

> **一个用来衡量模型预测质量的数值。**

一般：

```text
Loss 越小
→
预测越符合训练目标
```

我们的训练目标实际上就是不断想办法让：

```text
Loss
```

降低。

---

## 十九、MSELoss 是固定用法吗？

不是。

代码：

```python
loss_fn = nn.MSELoss()
```

只是因为我们这里属于一个非常简单的：

```text
数值回归问题
```

MSE 是：

```text
Mean Squared Error
均方误差
```

简单理解：

```text
预测值和真实值差多少
↓
平方
↓
取平均
```

对于一个样本：

```text
prediction = 2
y = 3
```

大概就是：

$$
(2 - 3)² = 1
$$

但 Loss 函数并不是固定的。

不同任务会用不同 Loss。

比如分类任务常见：

```text
Cross Entropy
```

以后训练语言模型，预测下一个 Token 时，也会大量接触：

```text
Cross Entropy Loss
```

所以：

> `MSELoss` 只是今天这个问题适合使用的损失函数，并不是“训练模型必须用 MSELoss”。

---

## 二十、什么是 Backward？

算完：

```text
Loss
```

之后，我们知道模型错了，也就是函数里的其他变量导致计算的结果和我们期望的值差距过大。

但还有一个问题：

> weight 应该增大还是减小？bias 又应该怎么改？

于是：

```python
loss.backward()
```

开始发挥作用。

这一过程叫：

```text
Backward
```

也就是反向传播。

PyTorch 会利用自动求导系统，根据 Loss 一路往回计算：

```text
Loss 对 weight 的影响
Loss 对 bias 的影响
```

最终产生：

```text
Gradient
```

---

## 二十一、Gradient 到底是什么？

Gradient 中文一般叫：

```text
梯度
```

可以先把它理解成：

> **告诉我们当前参数往哪个方向变化，会让 Loss 发生什么变化。**

严格一点说，它表示：

```text
Loss 对参数的变化率
```

例如：

```text
weight.grad = -2
```

意味着在当前位置附近，weight 的变化会以某种程度影响 Loss。

对于最简单的梯度下降，我们通常沿着：

```text
负梯度方向
```

去调整参数，希望 Loss 下降。

注意：

```python
loss.backward()
```

只负责：

```text
计算 Gradient
```

它**不会真正修改 weight 和 bias**。

---

## 二十二、Optimizer 又是什么？

现在我们已经知道：

```text
参数应该怎么调整
```

接下来谁负责真正执行？

就是：

```text
Optimizer
```

中文：

```text
优化器
```

代码：

```python
optimizer = optim.SGD(...)
```

Optimizer 是一类：

> **根据 Gradient 更新模型参数的算法。**

---

# 二十三、SGD 又是什么？

SGD：

```text
Stochastic Gradient Descent
随机梯度下降
```

是一种非常经典的优化算法。

最简单的思想就是：

```text
新参数 = 旧参数 - Learning Rate * Gradient
```

今天选择 SGD，并不是因为大模型训练一定使用 SGD。

而是因为：

> **它足够简单，非常适合第一次理解参数怎么更新。**

实际深度学习和大模型训练里，还经常看到：

```text
Adam
AdamW
```

这些更复杂的优化器。

但它们仍然没有改变最基本的问题：

```text
利用 Gradient
↓
决定参数怎么更新
```

---

## 二十四、Learning Rate 是什么？

代码：

```python
lr=0.01
```

这里的：

```text
lr
```

就是：

```text
Learning Rate
学习率
```

Gradient 解决：

```text
应该往哪个方向调整
```

Learning Rate 解决：

```text
一次调整要走多远
```

例如：

```text
gradient = -2
learning rate = 0.01
```

SGD 大概：

```text
参数变化 = -0.01 * (-2) = +0.02
```

Learning Rate 太小：

```text
训练可能很慢
```

太大：

```text
可能一下走过头
甚至 Loss 越来越大
```

所以学习率属于模型训练非常重要的一种：

```text
Hyperparameter
超参数
```

它不是模型自己训练出来的，而是我们给训练过程设置的参数。

---

## 二十五、optimizer.step() 到底干了什么？

这句：

```python
optimizer.step()
```

才是真正：

> **修改模型参数。**

所以一定区分：

```text
loss.backward()
↓
计算 Gradient


optimizer.step()
↓
真正修改 Parameter
```

例如：

```text
旧 weight = 1

gradient = -2

learning rate = 0.01
```

执行一次 SGD：

```text
新 weight = 1 - 0.01 * (-2) = 1.02
```

模型参数真的改变了。

这才叫模型完成了一次“学习”。

---

## 二十六、zero_grad() 又是什么？

PyTorch 有一个容易被新手忽略的特点：

> **Gradient 默认会累加。**

例如第一次：

```text
weight.grad = -2
```

再调用一次：

```python
loss.backward()
```

可能变成：

```text
weight.grad = -4
```

而不是重新覆盖成：

```text
-2
```

所以正常训练循环通常：

```python
optimizer.zero_grad()
```

清除上一轮梯度。

注意：

```text
zero_grad()
```

清除的是：

```text
Gradient
```

而不是：

```text
weight
bias
```

模型之前学到的参数不会因此丢失。

这里有个疑问，为什么计算出的 `Gradient` 一定要清掉呢？为什么不能累加呢？

因为这个值只跟我们输入的参数和当时的`weight`、`bias`有关，如果我们训练一步后更新了`weight`、`bias`而不清理 `Gradient` 就会导致后续的计算失真，越训练可能效果越差。

还有一种情况下 Gradient Accumulation 下，可以累加，这个后续再解释。

---

## 二十七、现在重新看一次完整训练流程

到这里，我们就可以把之前那几行代码完整解释出来：

```python
prediction = model(x)
```

表示：

```text
使用当前模型参数
进行一次预测
```

---

```python
loss = loss_fn(prediction, y)
```

表示：

```text
比较预测和正确答案
看看模型错了多少
```

---

```python
optimizer.zero_grad()
```

表示：

```text
把上一轮 Gradient 清掉
准备重新计算
```

---

```python
loss.backward()
```

表示：

```text
从 Loss 开始反向计算
得到每个可训练参数的 Gradient
```

---

```python
optimizer.step()
```

表示：

```text
Optimizer 根据：

Gradient
+
Learning Rate

真正更新模型参数
```

然后重新进入：

```text
下一次 Forward
```

整个过程不断循环：

```text
输入训练数据
      ↓
    Forward
      ↓
  Prediction
      ↓
     Loss
      ↓
   Backward
      ↓
   Gradient
      ↓
Optimizer.step()
      ↓
模型参数改变
      ↓
重新开始
```

这就是最基本的模型训练闭环。

## 二十八、最后彻底搞懂 Sample、Batch、Step、Epoch

这些词以后几乎每天都会看到。

### Sample：一条训练数据

例如：

```text
x = 1
y = 3
```

这是：

```text
1 Sample
```

所以：

> **Sample 是数据单位。**

---

## 二十九、Batch：一次拿多少条 Sample 来计算

假设：

```text
Dataset = 1000 Samples
```

但 GPU 一次只能处理：

```text
100 Samples
```

就分成：

```text
Batch 1：1～100
Batch 2：101～200
...
Batch 10：901～1000
```

于是：

```text
batch_size = 100
```

所以：

> **Batch 是一次训练计算所使用的一组 Sample。**

为什么要 Batch？

显存限制是最直观的原因。

除此之外，小批量训练本身也是现代神经网络优化的基本方式。

---

## 三十、Step：模型真正更新一次参数

如果普通训练：

```text
一个 Batch
    ↓
Forward
    ↓
Loss
    ↓
Backward
    ↓
optimizer.step()
```

就是：

```text
1 Optimizer Step
```

所以：

> **Step 是参数更新单位。**

---

### 一个 Batch 一定等于一个 Step 吗？

不一定。

以后会遇到：

```text
Gradient Accumulation
梯度累积
```

例如 GPU 一次只能处理：

```text
4 Samples
```

但希望综合：

```text
16 Samples
```

可以：

```text
Batch 1
4 Samples
↓
Backward

Batch 2
4 Samples
↓
Backward

Batch 3
4 Samples
↓
Backward

Batch 4
4 Samples
↓
Backward

最后：
optimizer.step()
```

于是：

```text
4 Batches
```

只产生：

```text
1 Optimizer Step
```

所以以后看训练日志时，要留意：

```text
Step 到底指 Batch Step
还是 Optimizer Step
```

在本文里，我把 Step 理解为：

> **参数真正更新了一次。**

---

## 三十一、Epoch：整个数据集完整学习一遍

还是：

```text
Dataset = 1000 Samples

batch_size = 100
```

一共有：

```text
10 Batches
```

当：

```text
Batch 1
...
Batch 10
```

全部处理完：

```text
1000 条数据全部被模型看过一次
```

就叫：

```text
1 Epoch
```

如果：

```text
epochs = 3
```

表示：

```text
第 1 遍：
完整训练全部 Dataset

第 2 遍：
再完整训练一遍

第 3 遍：
再完整训练一遍
```

因此：

> **Epoch 是数据集遍历单位。**

---

## 三十二、四个概念可以这样记

我觉得下面这句话最好记：

```text
Sample = 数据单位

Batch = 计算单位

Step = 参数更新单位

Epoch = 数据集遍历单位
```

比如：

```text
Dataset = 1000 Samples

batch_size = 100

epochs = 3
```

普通情况下：

```text
1000 Samples
      ↓
每 100 个组成 Batch
      ↓
10 Batches
      ↓
大约 10 Steps
      ↓
1 Epoch


重复 3 次
      ↓

3 Epochs
大约 30 Steps
```

如果加入梯度累积：

```text
Batch 数量
```

和：

```text
Optimizer Step 数量
```

就不一定相同了。
